# Poom-Pai 개발 오케스트레이터

**실행 모드:** 서브에이전트 위임(순차). 단계가 서로의 산출물 파일에 의존하고 에이전트끼리 대화할 필요가 없어 `Agent`를 차례로 한 번씩 호출한다.

## 0단계: 맥락 확인
- `_workspace/`가 있고 일부 수정 요청이면 해당 단계만 다시 실행한다. 새 요청이면 기존 폴더를 `_workspace_{타임스탬프}`로 옮긴 뒤 시작한다.
- 변경이 작으면(파일 1~2개, 로직 변경 없음) 1단계를 건너뛴다. 기능 추가나 정산·데이터 모델 변경은 전체를 거친다.

## 단계
| 단계 | 호출 | 산출물 |
|---|---|---|
| 1. 설계 | `Agent(subagent_type: "poompai-architect")` | `_workspace/01_architect_plan.md` |
| 2. 구현 | `Agent(subagent_type: "poompai-developer")` | 소스 + `02_developer_changes.md` |
| 3. 검증 | `Agent(subagent_type: "poompai-qa")` | `_workspace/03_qa_report.md` |
| 4. 보완 | QA에 `실패`가 있으면 2→3을 반복(최대 2회) | 갱신된 보고서 |

각 호출 프롬프트에 요청 원문과 앞 단계 산출물 경로를 명시한다. 변경이 서로 다른 화면에 독립적으로 걸치면 2단계를 파일 영역별로 병렬 호출해도 되지만, 같은 파일을 두 에이전트가 건드리지 않게 나눈다.

## 오류 처리
- 에이전트 실패는 1회 재시도하고, 다시 실패하면 누락 사실을 사용자에게 보고한다.
- QA 2회 보완 후에도 실패하면 남은 문제를 보고서 그대로 사용자에게 전달한다.
- 커밋·푸시는 사용자가 요청할 때만 한다.

## 최종 보고
변경 파일, QA 결과(통과/실패/확인불가), 남은 위험을 짧게 요약한다.

## 테스트 시나리오
- 정상: "참석자별 정산 내역 모달에 합계 줄 추가" → 설계 → 구현 → QA 통과 → 요약.
- 오류: 구현 뒤 `tsc` 실패 → QA가 실패 보고 → 개발자가 수정 → 재검증 통과. 2회 후에도 실패하면 보고서를 그대로 전달.
